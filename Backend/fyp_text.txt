Abstract
The beauty and salon business is really taking off. A lot of salons still do things the old way when it comes to making appointments and dealing with clients. This old way of doing things causes problems like scheduling mistakes, long waits and clients who're not happy. To fix these problems we came up with Beauty Personalized by AI, which's a website and mobile app that uses artificial intelligence to make booking and managing the salon easier.
Customers can use Beauty Personalized by AI to find salons look at the services they offer book appointments pay for things online and even get beauty tips based on their face shape, skin color, hair and what they like. Salon owners can use a dashboard to manage their services, appointments, promotions and client list. The people in charge can keep an eye on the website from their own dashboard. We built the website with the help of Reactjs, FastAPI, Supabase and Render. So Beauty Personalized by AI makes things easy, for clients. Automates the process making it secure.
Keywords: Artificial Intelligence, Salon Booking System, Beauty Recommendation System, Flutter,Render, FastAPI, Supabase, Appointment Management.

Introduction
Technological changes have also brought transformations in how various services are used, such as salon and beauty services. Currently, there is an increased preference for online portals where one can quickly locate salons, compare various services offered, schedule appointments and make payments. However, some salons still use manual ways of making appointments and management such as calling, recording everything manually, and walk-ins. This causes issues such as booking problems, wait times, and record keeping.
Beauty Personalized by AI is an application on web and mobile phones that facilitates the process of salon booking and management. Customers will be able to search salons, look for services offered, make appointments, make payment, and get personalized recommendations on hairstyle and beauty related services based on Artificial Intelligence. This is made possible by analysis of the users' skin tone, facial features, hair type, and personal preferences. 
The salon owners can manage their profiles, services offered, booking, prices and promotions, as well as the customer information from a single dashboard. Meanwhile, administrators can take care of users, salons, and the whole system.
Problem Statement
The main problems with salons are:
Manual booking is an issue because it causes scheduling conflicts and people have to wait for a long time to get an appointment.
Customers have a time comparing different salons and the services they offer and they also have to check prices and available time slots which is not easy.
Most salon platforms do not use intelligence to give customers personalized suggestions.
Salon owners do not have one system to manage everything like appointments and payments and customer information.
Doing things manually leads to mistakes. It slows down the business.
So we really need an AI-powered salon booking and management platform to make things easier for salons and their customers and to give people personalized beauty recommendations and to make booking appointments simpler and to automate how salons do things. That is why we need an AI-powered salon booking and management platform, for salon operation
Objectives
This project is about creating a salon booking and management platform that uses intelligence to make things better for customers and help salon owners run their business in a smarter way.
The main goals of this project are:
We need to make a website and a mobile app that customers, salon owners and people who manage the system can use.
We want customers to be able to look for salons check out the services they offer and book a time to go online.
The salon booking and management platform will use intelligence to give customers ideas for hairstyles, beauty services and salons that are a good fit for them.
The platform will have a way for customers to pay online and get reminders about their bookings. Salon owners will be able to use the salon booking and management platform to control the services they offer the appointments they have how much they charge any deals they want to offer and the information they have, about their customers.
Scope of the Project
In Scope:
There is an online platform (React.js) and mobile app (Flutter) for customers and salon owners.
Sign up of salon, salon profile and service features management.
Recommendations for beauty using Ai: face shape detection, skin tone, hairstyle, and Chatbot assistance.
Appointment booking which can be done in real time, with real-time slot availability.
Integration of secure payments through Stripe payment gateway.
Reviews and ratings of salons and their services from customers.
Management panel to manage users and monitor the system.
Out of Scope:
E-commerce part delivery of physical beauty products.
Integration of third-party logistic or courier services.
Hardware management of the salons.
Regulatory data integration

6.2 Deployment Setup
This infrastructure is set up across the following services: Vercel for the website, Render for the backend, and Supabase Cloud for the database and authentication
Website (React.js on Vercel): The React.js website is deployed to Vercel. Each commit to the master branch on GitHub automatically starts a new deployment process. Supabase URL and API keys are securely stored in the Vercel project settings.
Mobile App (Dart / Flutter): The mobile application is developed with Flutter and compiled as 'flutter build apk' for Android. It uses the environment variables from a .env file to connect to the backend and Supabase (this file is not kept under version control). 
Backend (FastAPI on Render): This FastAPI application is deployed to Render and processes all REST API requests, booking logic, payment registering, and calling of the Gemini API. HTTPS protocol is configured via Render settings.
Database and Auth (Supabase Cloud): Supabase Cloud provides PostgreSQL database with real-time capabilities and authentication functionality, as well as file storage. RLS policies are implemented in the database for role-based access without additional middleware. 
Payment: Cash payment only is used by the system. Users pay in cash while being serviced. The payment details are recorded in the Supabase database
6.3 Algorithms
The following are the main custom algorithms built for Beauty Personalized by AI. Full source code is not included. Only the key steps and logic are described.
Algorithm 1: Face Shape Detection and Hairstyle Recommendation
Input: Customer photo (uploaded image)
Convert the uploaded image to base64
Send to Gemini Vision API with the prompt:
"Look at this face. Classify the face shape as one of: Oval, Round, Square, Oblong, or Heart. Return JSON: {shape, confidence, top3_hairstyles}"
Read the response. If confidence is below 0.70, ask the user to upload a clearer photo.
Match the face shape to the hairstyle list and return the top 3 suggestions.
Output: [{hairstyle, reason, confidence, image_url}]
Algorithm 2: Booking Slot Conflict Check
Input: salon_id, service_id, selected_date_time, duration_minutes
Calculate slot_end = selected_date_time + duration_minutes
Search Supabase bookings table: SELECT id FROM bookings WHERE salon_id = :salon_id AND status != 'cancelled' AND start_time < slot_end AND end_time > selected_date_time
If any result is found: return error 'Slot is not available'
If no conflict: save booking with status = 'pending' and return booking_id
Output: booking_id or error message
Algorithm 3: AI Service Recommendation
Input: customer_id
Get customer profile from Supabase: skin_tone, hair_type, face_shape
Get the customer's 5 most booked service types from booking history
Build a prompt: "Customer details: skin = {skin_tone}, hair = {hair_type}, face =
{face_shape}.Most used services: {service_types}.
Suggest 5 salon services. Return as JSON array."
Send to Gemini API, read the response, and match with available services in Supabase
Output: List of recommended services sorted by match score
Algorithm 4: Cash Payment Recording
Input: booking_id, amount_paid, payment_date
Check that the booking exists and is in 'confirmed' status
Record payment in the payments table:
INSERT into payments (booking_id, amount, date, method, status) VALUES (:booking_id, :amount, :date, 'cash', 'completed')
Update booking status to 'paid' Send booking confirmation notification to the customer Output: Payment recorded successfully

Future work
At present, the system provides users with beauty recommendations and assistance in scheduling services provided by salons through the use of artificial intelligence. Nevertheless, there is much room for improvement.
One of the enhancements could be the implementation of the Beauty Reels functionality. This would be the feature where videos similar to those that one may find on Instagram and TikTok would be uploaded by salons, hair stylists, makeup artists, beauty influencers and others. They would show various hairdos, techniques for doing makeup, skin care advice and ways in which one may improve their appearance. In addition to watching these videos, users would be able to discuss them and even book an appointment at salons or services advertised in the videos. Thus, the system would become more entertaining and interactive.
It would also be beneficial if there was an in-system online store for beauty products. This would allow people to purchase beauty, skin care and hair care products recommended by artificial intelligence or used at salons. People would have the opportunity to view products, get information regarding them, place orders and pay online in the system without having to visit other sites.

Glossary of terms
The following terms are used throughout this document. Definitions are specific to their usage in the context of Beauty Personalized By Ai. 
Term
Definition
PB-ID
Product Backlog Identifier a unique code assigned to each user story in the product backlog 
(e.g., AM-01, BK-03, AI-06). Used throughout the traceability matrix in Chapter 7.
Sprint
A fixed-length development cycle used in Agile methodology. This project used 7 sprints 
ranging from 4 to 8 weeks each, totalling 42 weeks (2 semesters).
User Story
A feature description written from the end user's perspective: 'As a <role>, I can
<action>.' All 68 PB-IDs in this document follow this format.
Acceptance Criteria
The conditions that must be met for a user story to be considered complete and 
accepted by the product owner (supervisor).
Story Points
A relative unit of effort estimation used in Agile sprints. Total story points across 
all 7 sprints: 273.
FastAPI
A modern Python web framework for building REST APIs, used as the sole backend
for Beauty Personalized by AI. Deployed on Azure App Service.
Flutter / Dart
Google's open-source UI toolkit and programming language for building natively
compiled mobile apps from a single codebase. Used for the Android and iOS mobile app.
React.js
A JavaScript library for building user interfaces. Used for the web frontend 
(salon owner dashboard, admin panel, customer web app).
Tailwind CSS
A utility-first CSS framework used to style all React.js frontend screens
consistently.
Supabase
An open-source database, authentication, real-time subscriptions, and file storage as a
managed cloud service.
RLS
Row-Level Security a PostgreSQL/Supabase feature enforcing data access rules at the 
database level per user role (Customer, Salon Owner, Admin).
Gemini API
Google's generative AI API (gemini-1.5-pro / gemini-1.5-flash) used for face shape detection, skin tone and hair type analysis, AI chatbot, and personalized recommendations.
Vercel
A cloud deployment platform with automatic CI/CD from GitHub, used to host the 
React.js web frontend.
Render
Cloud hosting platform used to deploy and host the FastAPI backend. No local
Installation needed.
API
Application Programming Interface a set of endpoints allowing software components 
to communicate. All business logic is exposed via the FastAPI REST API.
RBAC
Role-Based Access Control restricts system access based on user roles: Customer,
Salon Owner, and Admin. Enforced via Supabase RLS policies.
C4 Model
A software architecture visualisation framework (Context, Container, Component, Code)
used to document the system architecture in Chapter 5.
TID
Test Case Identifier a unique code assigned to each test case (e.g., TC-101, TC-504) 
used in the traceability matrix (Chapter 7).
NFR
Non-Functional Requirement a system quality attribute such as performance (NFR-01),
 security (NFR-02), and scalability (NFR-03).
CDN
Content Delivery Network used to serve Flutter-uploaded videos and images (service photos)
 stored in Supabase Storage via optimized URLs.
